1. Product Overview

TMC Food Hub is a multi-role food ordering platform built as a full-stack web application. The system currently supports customers, restaurant owners, and administrators through separate experiences and role-aware backend APIs.

  • Customers browse restaurants, place orders, upload payment proofs, track deliveries, manage profiles, and submit reviews.
  • Restaurant owners manage menus, categories, stock levels, order fulfillment, payment settings, analytics, and store operations.
  • Administrators supervise customers, restaurants, disputes, reviews, payouts, promotions, platform settings, permissions, and security configuration.

2. Technology Stack

  • Frontend: React 19, Vite, React Router, Axios, React Leaflet, Lucide React, jsPDF, html2canvas
  • Backend: Laravel 12, Sanctum, Eloquent ORM
  • Project layout: `frontend` for the web application and `backend` for the API and data layer
  • Main data domains: users, restaurant owners, categories, menu items, orders, order items, reviews, promotions, platform settings, security settings, and activity logs

4. Customer-Facing Features

4.1 Public Website and Content Implemented

  • Home page with hero, about, features, how-it-works, testimonials, services, events, FAQ, contact, and footer sections.
  • Dedicated pages for services, support, FAQ, events, announcements, and news/blog content.
  • Announcement detail pages include a PDF export action built with jsPDF and html2canvas.
  • Theme support is shared through a central theme context.

4.2 Authentication and Profile Implemented

  • Email and password login.
  • Google login and Google signup.
  • Multi-step signup flow with email OTP verification and legal acceptance.
  • Forgot-password flow with reset OTP verification.
  • Profile editing, address management, delivery instructions, and password changes.
  • Token-backed session persistence using local storage and backend user revalidation.

4.3 Restaurant Discovery and Menus Implemented

  • Restaurant search by name or cuisine.
  • Cuisine filters, dietary filters, sorting, and pagination.
  • Restaurant-specific menu pages with dynamic category tabs, item search, dietary filtering, and similar restaurants.
  • Availability-aware menu rendering with stock and out-of-stock states.

4.4 Cart, Checkout, and Payments Implemented

  • Login-required add-to-cart flow.
  • Single-restaurant cart enforcement.
  • Persistent cart storage in local storage.
  • Checkout with ASAP delivery or scheduled delivery up to 7 days ahead.
  • Restaurant-specific payment methods for COD, GCash, Maya, and bank transfer.
  • Non-COD orders redirect to payment proof upload after placement.

4.5 Orders and Tracking Implemented

  • My Orders page with ongoing, completed, and cancelled tabs.
  • Polling-based order refresh every 5 seconds through shared order context.
  • Tracking page with timeline, route map, rider card, payment status, receipt preview, and cancellation timer.
  • Reorder behavior for completed orders.

4.6 Reviews and Feedback Implemented

  • Review submission restricted to delivered orders.
  • Star ratings, text feedback, and backend support for review photos.
  • Restaurant rating summary and star distribution.
  • Helpful vote toggle on reviews.

5. Restaurant Owner Features

5.1 Owner Authentication Implemented

  • Owner login with dedicated token issuance.
  • OTP-backed owner registration with business details and merchant agreement acceptance.
  • Owner token refresh and logout flows.

5.2 Owner Dashboard Shell Implemented

  • Responsive owner portal with grouped sidebar navigation.
  • Notification panel, search UI, owner/store profile area, and dark mode toggle.
  • Welcome banner for newly onboarded stores.

5.3 Orders, Store Controls, and Payments Implemented

  • Owner-only order view tied to restaurant ownership.
  • Order status progression controls.
  • Online payment confirmation and rejection.
  • Store operations for open, paused, closed, auto-accept, manual confirmation, and prep time.
  • Payment settings for COD, GCash, Maya, and bank transfer.

5.4 Inventory, Menu, and Categories Implemented

  • Stock updates, refill actions, and low-stock awareness.
  • Menu item creation, editing, deletion, image upload, pricing, description, and category assignment.
  • Category creation, editing, deletion, and reorder support.
  • Availability toggles and auto-toggle behavior based on stock.

5.5 Reviews, Analytics, and Settings Implemented

  • Owner review inbox with reply support.
  • Analytics data for revenue, orders, top items, heatmaps, and high-value orders.
  • Settings tabs for account, security, notifications, restaurant profile, store operations, and payment.
  • Map-based restaurant location editing using Leaflet.
  • Owner order tools include PDF receipt export support.

5.6 Owner Promotions Implemented

  • Promotions management includes search, status filters, create flow, and metrics cards.
  • Promotion listings support ongoing campaign visibility and lifecycle management.

6. Administrator Features

6.1 Dashboard and Oversight Implemented

  • Dashboard KPIs for partner count, platform revenue, active restaurants, and total customers.
  • Revenue chart, restaurant applications, alert stream, and quick actions.
  • Platform-wide order management.
  • Customer administration and restaurant partner administration.

6.2 Moderation, Finance, and Analytics Implemented

  • Reviews moderation with status grouping.
  • Disputes handling with refund and rejection flows.
  • Payments and payouts management.
  • Analytics and performance overview sections.

6.3 Promotions and Settings Implemented

  • API-backed promotions with create, edit, delete, inspect, and extend actions.
  • Settings for platform identity, commission, notifications, admin management, roles, activity logs, security, and appearance.
  • Roles and permissions editing backed by database tables.
  • Activity logs with masked IP display.

6.4 Admin Exports Implemented

  • Export modals are present in customers, restaurants, reviews, analytics, payments, and promotions.
  • Administrative reporting includes export actions across key management and analytics sections.

7. Backend and System Capabilities

  • Role-based Sanctum authentication for customers, owners, and admins.
  • Email OTP verification for signup and OTP-driven password reset.
  • Google credential verification endpoints for customer authentication.
  • Store-status enforcement before order creation.
  • Stock deduction on order placement and stock restoration on cancellation.
  • Receipt upload plus owner-side payment confirmation or rejection.
  • Verified-order review enforcement and helpful-vote support.
  • Media serving endpoint for stored uploads.
  • Platform settings, security settings, activity logs, and roles/permissions support.
Implementation Coverage Summary
  • Owner operations cover menus, categories, inventory, promotions, payments, analytics, reviews, and store settings.
  • Admin operations cover exports, moderation, disputes, analytics, payouts, promotions, settings, and activity logs.
  • Customer order flow covers discovery, cart, checkout, receipt upload, tracking, order history, reorder, and reviews.
  • Platform services include authentication, media handling, promotions logic, settings management, and validation rules.
